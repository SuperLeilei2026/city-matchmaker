# 毕业第一站：参赛定位与风险

更新：2026-10-14。本页描述 v0.6 候选，不代表晋级、App Hub 审核或获奖。

## 项目表达

**两座城上同一站台，找出最可能改变决定的那件事。**

旧版“推荐一座城市”容易落入伪精确。v0.6 把创意集中在一个更真实的行为上：用户已经在几座城市间纠结，应用把两种未来生活写成三幕对局，审计原始判断，最后生成可以执行的双城通行证。

## 90秒演示

1. **10秒：** 小陈带入深圳、杭州，说“我更倾向深圳，因为成本低、具身智能机会更多”。
2. **15秒：** 选择具身智能、散步、阅读、4000元预算和潮湿红线；指出深圳“红线待核”、杭州“条件冲突”。
3. **35秒：** 快速完成三幕：第一份工作选深圳、普通下班后平局、落地代价选杭州。
4. **15秒：** 展示假设审计：杭州2638元、深圳3696元；泛 AI 资料不能证明具身智能机会；深圳湿度未知。
5. **10秒：** 请求 Agent 找关键一问，强调它不改排序、不替用户选城，确认后才保存任务。
6. **5秒：** 用户亲自选择“先验证深圳”，展示杭州仍作为可改签备选。

## 与“写作与创作”赛道的关系

本项目的写作价值不在于生成更多城市宣传文案，而在于**把一个含混的人生判断改写成两份可比较的生活草稿，并把结尾写成现实行动**。

三幕分别回答“我会做什么工作”“普通下班后怎么过”“我愿意承担什么代价”；通行证保留原始信念、反例、未知和改选条件。这是一种交互式决策叙事。系统 Agent 的作用是编辑问题，而不是替用户续写一个确定结局。

赛道风险仍然存在：评委也可能把它理解为生活决策工具。答辩必须直接展示“三幕如何改变用户对自己那句话的理解”，不能只展示酷炫界面或候选排序。

## 当前优势

- **题目真实：** 聚焦已有候选间的纠结，比全国推荐更贴近日常决策。
- **动作有含义：** 每一幕都要求用户表态或承认信息不足。
- **结果能行动：** 通行证给出岗位、住房和日常核验任务。
- **视觉有记忆点：** 双轨站台把两种生活的冲突可视化。
- **Agent 权限清楚：** 它只能提出关键问题，无法偷偷改结果。
- **边界可信：** 明确不预测幸福、录取、薪资和 WLB。

## 最可能失分的地方

1. **真实模型证据仍然有限。** 当前签名包已在完整 Shell 中完成一次 MiniMax-M3 调用、确认、存档与重启恢复；Kimi、故障切换和更多输入仍未验证。
2. **用户价值还未实测。** 小陈、小雷目前是回归档案，不是已完成访谈或可用性研究。
3. **城市证据不对称。** 兴趣与气候资料覆盖不同；未知必须继续显式呈现。
4. **移动端未实测。** macOS 参考宿主和响应式浏览器不等于 Android/HarmonyOS 真机。
5. **发布仍未完成。** 本地 stamp/check 不能称为 App Hub 上架。
