# 项目定位与参赛场景

更新：2026-10-03。本文区分产品定位、官方场景说明与原报名信息，不代替主办方对报名信息的确认。

## 这个产品解决什么问题

**毕业生城市探索与生活决策。** 用户还没确定毕业后去哪座城市，应用帮助其说清职业方向、生活偏好与底线，形成有依据的候选，并通过反馈进一步比较。

对外的一句话：**把“毕业去哪儿”变成一场能说清理由、听取反馈、逐步缩小范围的城市探索。**

它目前不是路线导航，也不是自动求职或现实幸福率预测。城市数据是带来源和未知项的有限资料库，不能替代具体岗位、住房和通勤调查。

## 与官方场景的关系

官方列出的十二个场景包括导航、写作与创作等，没有单列“城市推荐”或“生活决策”。官网同时说明这些是选题建议，可以联动多个场景、统一参评。

- **最准确的产品分类：** 城市探索与生活决策。可作为原创场景说明，不把这一名称冒充官方已设立的独立赛道。
- **相关场景：** 导航与出行。但现阶段主要回答“去哪座城生活”，没有路况、路线或出发计划，不能宣称已完成官方导航场景的任务。
- **原报名信息：** 写作与创作。当前没有可修改、比较和确认的创作作品流程，因此不能仅凭城市文案或分享图宣称完全贴合这一场景。是否调整正式登记，应由参赛者与主办方确认；本次代码更新不更改外部报名记录。
- **建议重点展示：** 应用层的 Agentic 任务、人对修改的控制、修改前后结果与失败处理。最佳 Agentic 是评奖方向，不是一个新增的报名场景，也不代表本作品已获认可。

不为贴标签强行加入一套无关的写作功能。优先把城市决策任务做好。

## 要证明的 Agent 任务

1. 用户在已有推荐上补充一段自由反馈。
2. 系统 Agent 根据允许使用的偏好和候选资料，提出受限制的结构化修改。
3. 应用列出修改内容，用户可以确认或拒绝；确认前不改变匹配结果。
4. 确认后，应用更新偏好、重新计算候选、保存，并核验保存后的状态。
5. 显示发生了什么变化；资料不足或候选不变时如实说明。无效、过期或失败的响应不能修改资料。

Agent 负责理解自由表达、提出操作；本地规则负责可复核的匹配和硬条件。不得将规则结果写成模型输出，也不得将测试响应当成真实模型成功调用。当前实现与实际验收状态以 [公开版本说明](publication.md) 和 [演示材料](demo.md) 为准。
