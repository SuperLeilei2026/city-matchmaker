# Joy City v0.4：先看城市，留下喜欢的

更新：2026-10-05。本文区分产品设计、已知依据和仍待验证的假设。原生应用是本版交付入口；辅助 Web 暂保留 v0.3 交互。

## 产品承诺

**给想做 AI 产品的你，找一座愿意留下的城市。**

先让用户看到一种具体生活，再决定是否值得深入了解。第一屏不需要回答问题，也不宣称已经了解这个人。第一阶段的成果是两座想继续了解的城市；补充明确偏好后，才能进一步比较。

“喜欢这张卡”不等于“适合在这里长期生活”。应用不预测幸福概率、收入、就业或创业成功；旅游资源也不能直接证明工作日的生活质量。

## 一条主路径

1. **看一座城市。** 城市名、日常插画、一句吸引力、一句代价。只有“留着看看”和“下一座”两项主要操作。
2. **留两座，放在一起看。** 第一座留下后继续浏览，第二座留下后直接比较。最多两座，不能重复加入；可移除后换一座。
3. **拿不准时，再问一件事。** 用户主动打开追问，才从尚未填写、且两城有已知差异的维度中选一题。回答不保证改变先后；找不到有依据的问题，就说明资料还不足。

个人资料、来源、完整取舍和应用 Agent 都是按需进入。浏览完一轮有明确终点，可以重看；不会无限循环，也不会把翻过的城市当成用户拒绝。

## 每次操作究竟改变什么

| 操作 | 保存什么 | 不据此推断什么 |
| --- | --- | --- |
| 下一座 | 本轮已浏览城市与位置 | 不推断讨厌这座城，不排除，不改五维 |
| 留着看看 | 至多两座收藏城市 | 不推断性格，不给城市暗加分 |
| 从比较中移除 | 取消该城收藏 | 不等于永久拒绝 |
| 回答一个场景 | 本人确认的五维选项 | 不由城市标签反推其他选项 |
| 修改天气底线 | 明确避开项及软硬程度 | 未核验的城市天气不当成已满足或不满足 |
| 明确不考虑该城 | 拒绝记录 | 不因换介绍人或重开一轮而恢复 |
| 重新看一轮 | 重置本轮浏览记录 | 不清空画像、收藏和明确拒绝 |

新用户没有偏好时采用稳定的浏览次序，不把第一张卡称为“最适合你”。已有本人明确选择时，候选可以按规则排序，但仍保留来源和未知项。保存资料、切换视角、编辑返回和重启不得改变用户未修改的条件。

## 比较与一次追问

比较先展示用户自己留下的两座城。已填写维度按同一规则计算；没有答案时不做个性化判定。

追问只从未填写维度中挑选：至少有一个选项在两城都存在已知线索且分档不同，再按差异与当前视角权重排序。未知不能被当成差；若只有一城有资料，不凭这点制造一道有标准答案的题。问题的目的是确认用户在意的事，不承诺答完必然分出赢家。

城市分档包含编辑判断的范围与未知范围。两城范围重叠时不宣称唯一更适合；一个确定的回答也可能不足以消除城市资料的不确定性。

## 城市短卡与图片

`data/cities.json` 中的 `card` 保存吸引力、代价、素材路径和来源 ID。内容从已有城市库提炼，不增加新的量化结论。生活插画为原创 SVG，不是实景照片、地图、房源或路线证据；不能据此承诺某个住处到公园的距离。

卡片刻意保留代价，避免把所有城市写成同一种美好生活。完整来源与未知项留在详情中，主卡不堆证据列表。

## 两位介绍人

ENFP 线条小狗侧重日常生活，INTP 黑白德文猫侧重职业期待。角色放在辅助位置，不要求先选角色，也不加入双方辩论。

两者共享城市事实与本人底线，切换的是明示的规则权重。MBTI、星座、院校、年龄不决定排序；人格名称是角色表达，不是对用户的心理测验。

## 数据能支持到哪里

八城包括北京、上海、杭州、深圳、广州、成都、武汉、南京，保留32条来源。136条 Joy 信号中，47条为人工整理、89条未知，没有 Joy 分档被标为实测值。

当前比较主要有活动、户外恢复和 AI 交流实践线索。稳定关系、具体公司作息、安静住处和职业持续性资料不足。用户提出这些需要时应保留，而不能因缺资料就换成别的需求。房租、居住方式和通勤也要在具体岗位、房源与路线下核验。

五维规则和未知处理见 [匹配模型](matching-model.md)。新的浏览/收藏状态与比较参考实现见 `core/discovery.mjs`；原生 UI 在 `tools/main.template.splash`，生成到 `bundle/main.splash`。

## 需要验证的产品假设

**这版是否比问卷更容易开始，仍需真实体验。** 首要观察：用户能否不看说明就留下两座城；是否能说出喜欢的具体生活点和愿意承担的代价；比较后是否更清楚下一步想了解什么。

主要风险是用户只凭城市名或插画收藏、不同城市的日常被写得过于相似，以及短卡令人误以为工作与生活资源必然可达。验证这些问题时优先调整素材与取舍表达，不自动增加必填问题。

## 原生、Web 与模型

v0.4 简化的是 OctoScript 原生流程。Web 仍保留旧交互作为设计和规则研究材料，不能当作本次原生效果的演示。

应用 Agent 仍通过宿主提出受控修改，用户确认后执行。提案绑定实际查看的城市，不自动针对排序第一城；切页、换城、资料变化或取消会使旧提案失效。五维由用户手选，CM1 的有效模型动作主要是追加天气避开项或明确排除当前城市。

`card-host` 无模型服务；官方 Desktop 完整 Shell 已完成一次隔离合成资料的 MiniMax-M3 全链路验收，见[真实 Agent 报告](../qa/real-agent-e2e-v0.4/README.md)。测试注入仍只检验保护逻辑，不当作真实 MiniMax/Kimi 成功；Kimi 与其他平台未验证。分享默认不含身份与自由反馈，原生与宿主数据边界见 [隐私说明](privacy.md)。
