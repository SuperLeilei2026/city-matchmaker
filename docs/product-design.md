# 毕业第一站 v0.6：双城决策实验室

更新：2026-10-13。本文区分已实现行为、产品判断与待验证假设。

## 一句话产品

**把两种都可能成立的城市生活放在同一座站台上，找出最可能改变决定的那件事。**

## 为什么不再把“推荐一座城”当作核心

两份样本暴露了旧模型的逻辑跳跃：

- 小陈认为深圳成本更低，但当前同口径小户型平均套租为杭州2638元、深圳3696元；两者仍都不能代表岗位附近真实房源。
- “具身智能”曾被粗略并入“AI/互联网”，无法区分机器人、硬件、算法、供应链和产品岗位。
- 小雷认为成都压力小，但 WLB 主要来自公司、团队和岗位，城市气质不能替代调查。
- 游泳、健身、阅读等兴趣缺少同口径城市或街区证据，强行参与分数只会制造画像准确的错觉。

因此，v0.6 的核心需求不是“全国哪座城最适合我”，而是“我在几座城市之间纠结，自己依赖了哪些未经验证的判断，下一步先查什么”。

## 双入口

### 我已经在纠结几座城

用户直接选择2–4座现实候选。这是主入口，因为真实决策通常已经被工作机会、家庭、地域认知和个人经历缩小。

### 我还没有方向

用户用积木式生活取舍、行业、兴趣与预算生成前三站。内部排序只负责缩小范围；最终仍由用户留下两座。

## 三幕双城 PK

对局开始前，用户写下为什么更倾向其中一城。这句话只进入假设审计，不进入排序。

1. **第一份工作：** 宽行业线索、具体职业方向和仍未知的公司条件。
2. **普通下班后：** 用户真正愿意重复的散步、阅读、游泳、健身或演出。
3. **住下去的代价：** 城市级租金压力、具体住房与通勤、气候健康红线及愿意承担的代价。

每幕并排呈现两段生活草稿、已有证据、编辑判断和未知。用户选择左边、右边或“还看不出”。三幕投票形成思考轨迹，不按多数票宣布赢家。

## 双城通行证

通行证保留：

- 先验证城市与备选城市；
- 用户原本相信的判断；
- 已有证据、反例和未知；
- 三幕选择轨迹；
- 三项现实核验任务及一项可选 Agent 任务；
- 什么新信息会让用户改选另一城。

“先验证”表示验证顺序，不表示最终定居结论。

## 排序与约束

内部候选顺序仍使用产业、已有兴趣证据和生活取舍，但主界面不展示总相合指数。预算与健康/气候红线从加权项中拆出：

- `clear`：当前没有已知冲突；
- `conditional`：现有资料显示条件冲突；
- `unknown`：关键资料缺失。

排序时约束状态先于偏好线索；未知不会被当作通过。预算高于城市租金基准后不继续加分。城市级平均租金只表达压力，不能得出具体房源可负担的结论。

## Agent 的角色

系统 Agent 是决胜提问官。它读取两城、三幕平局、用户担忧和资料缺口，返回一个可能改变决定的问题和一项行动任务。应用验证结构化响应；用户确认任务后才保存。Agent 不修改候选、不重排、不投票、不选择首城。

Web 没有模型服务，使用同一套本地规则。原生参考宿主没有模型时也能完整完成流程。

## 视觉与互动

视觉采用原创工业车站，而不是复刻《双城之战》：

- 深蓝夜站作为背景；
- 冷青与洋红表示左右两条城市线路；
- 信号黄提示证据、警报和关键行动；
- 分屏站台表现两套生活秩序的冲突；
- 车票升级为双城通行证，强调“可改签”。

赛博朋克风格服务于决策张力。它不能遮住约束状态、来源边界或下一步任务。

## 已实现与待验证

已实现：五阶段 Web 和原生流程、三幕 PK、无自动赢家、假设审计、约束状态、双城通行证、本地回退、Agent 协议保护、v1/v2/v3 存档迁移、两份固定档案回归。

仍未知：

1. 真实用户是否能说清自己依赖的假设；
2. 是否发现至少一个此前未意识到的信息缺口；
3. 是否愿意执行通行证上的现实核验任务；
4. 赛博视觉是否帮助理解，还是只带来短暂新鲜感。

下一轮应让小陈和小雷亲自试玩，并逐幕记录“说中了 / 完全不是这么回事 / 我需要什么证据”。在这之前，不增加更多人格题或城市，以免扩大未经验证的模型。
