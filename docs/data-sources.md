# 城市数据来源与使用边界

版本：六城首版；核验日期：2026-10-03。对应 `data/cities.json`，共 6 个城市、16 条来源。

## 这是什么数据

这是一份为可玩原型准备的、小范围的**公开资料加人工分档**数据。它用于提出值得进一步了解的候选城市，不是城市宜居榜、招聘预测、幸福概率或对居民性格的判断。

检索主要使用 agent-reach 的 Exa 路由，选用市政府、统计局、气象部门、官方规划/人才目录和 UNESCO 原始页面。武汉、南京、广州统计公报等另打开了原始网页核对正文；部分资料通过官方页面的搜索索引正文读取。`checked` 表示本次查阅日期，不表示每一个原站、PDF及链接已在所有网络环境下完成可用性测试。

产业资料主要为 2024 年历史背景和 2025 年发布资料。2026年已有更新公报的城市，也没有把本文件包装成“最新城市市场数据”；第一版保持明确年份，后续需要按共同口径更新。目录和规划只支持已写明的产业方向或自然条件，规划目标不当作完成事实。

## 0—3 到底表示什么

所有当前非空数值的 `featureEvidence.status` 都是 `editorial`，没有一个数值声称直接来自官方。来源提供事实背景，分档是项目编者的暂定判断，尚未经过毕业生样本验证。

- 产业/资源的 1：已有具体依据，但覆盖较窄或仅能确认存在。
- 产业/资源的 2：存在多种可辨认的产业或活动基础，可列入探索。
- 产业/资源的 3：当前资料显示明显的专门产业定位、多类型资源或文化生态，作为较强探索线索。
- 气候的数值越高表示越值得对该项敏感的用户留意，而非城市越差。1 表示相对温和但仍可能发生相关天气；2 表示明确季节性或气候背景；3 表示资料明确强调该项负担，例如酷热、湿热与湿冷。
- 0 保留给未来有充分依据的低强度情况。本版没有用“没查到”填 0。
- `null` 是未知。不能转成 0、默认舒服、默认便宜，或当成“不存在”。

分档不是同口径实测的城市横向排名；资料覆盖程度、产业统计口径和个人体验均有偏差。`coverage` 只能反映当前偏好对应的信息覆盖，不能显示成信心、匹配概率或幸福概率。推荐器应允许反馈纠偏，并列明未知项。

`nature` 描述资源而非家门口可达性；`live` 描述演出文化基础而非你喜欢的场次；`creative` 也不能概括广告、设计、影视、游戏等所有职业。

## 特意保留的未知

六城的 `cost`、`ball`、`quiet` 全部为 `null`。现有资料不足以回答预算内可租住房、球场开放/价格/球友、街区噪声等具体问题。上海/杭州等没有因为城市名就被赋“贵”，成都/武汉等也没有被赋“便宜”。

杭州与成都的 `cold`、成都与南京的 `live` 暂为 `null`。武汉、上海、杭州、南京的 `food` 暂为 `null`。没有取得证据不代表这些城市没有相应体验；后续应补充同口径信息，不能为制造推荐差异随意补分。

六城均保留：目标岗位实际录取机会与薪酬、预算内住房和通勤、社交与熟人支持、可支配休闲时间。学校、年龄、MBTI、星座，以及欣赏的人的人格标签不参与事实数据或城市分档。

经纬度是用于小地图排版的、保留一位小数的城市示意点，不是办公地点、城市边界或住宅坐标。不能由此计算回家时间、通勤时长或社交半径。

## 事实与创作文案

`tagline`、`persona` 和 `scenes` 是原创产品文案。`persona` 采用介绍人的比喻，不描述当地居民共同人格；每条 `scenes` 都以“一种可能的……”开头，是生活想象，不是已验证行程或结果保证。

`tradeoffs` 是需体验、查证或接受的具体条件，不制造租金、薪资、通勤与演出价格数字。用户的取舍与经历负责纠正初始判断，不能把用户拒绝解释成“你的 MBTI 不够典型”。

## 后续最值得补的证据

1. 把用户目标岗位拆到具体职能与资历，再采集带日期的招聘样本；产业存在与个人能否进入分开呈现。
2. 选定办公片区后，按真实住房条件核验租金、押付、交通时间；不能用全市平均收入代替。
3. 按用户偏爱的音乐/戏剧、球类、口味等类别查近期日程和场地，补齐目前的 null。
4. 以气象部门同一统计期的月度常年值完善气候分档，并区分天气极端、住房条件与个人体感。
5. 请真实毕业生反馈“为什么不喜欢首推”和“二轮是否更贴近”，再校准人工分档；不以点击或分享证明生活结果更好。
