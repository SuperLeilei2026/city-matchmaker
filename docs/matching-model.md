# 毕业第一站 v0.6：候选顺序与双城规则

更新：2026-10-13。当前实现是可复核的候选排序器与决策整理器，不是人格测验、幸福预测、就业预测或统计推荐系统。Web 规则位于 `core/departure.mjs` 与 `core/duel.mjs`；原生等价规则位于 `tools/main.template.splash`。

> `core/v3`、`data/v3` 与 [matching-model-v3.md](matching-model-v3.md) 是另一个仍在探索的全球 Joy City 数据契约，不是 v0.6 生产界面使用的规则。

## 输入

| 输入 | 作用 |
| --- | --- |
| 候选模式 | 已有候选时限定2–4城；无方向时在八城中内部排序 |
| 发展 ↔ 生活 | 在行业线索与生活兴趣之间分配内部偏好权重 |
| 安静 ↔ 热闹 | 热闹侧最多增加10%的活动线索权重 |
| 宽行业 | 技术、创意、制造、商业服务或探索中 |
| 具体职业方向 | 用于说明宽行业资料的边界和生成核验任务，不直接加分 |
| 兴趣 | 散步/户外、演出、饮食、游泳/健身/球类、阅读/安静；最多三个 |
| 月租上限 | 生成城市级住房压力约束，不进入偏好分 |
| 气候红线 | 生成健康/气候约束，不进入偏好分 |
| 原始倾向 | 进入假设审计，不影响初始排序 |
| MBTI/星座签名 | 只作表达，不参与排序 |

进入两城筛选的最小条件是：确认行业或选择探索中、至少一个兴趣、有效预算。已有候选模式还要求2–4座城市。

## 内部偏好分

设 `x` 为发展/生活轴，`s` 为安静/热闹轴：

```text
lively = 0.10 × max(0, (s - 50) / 50)
remaining = 1 - lively
careerShare = 0.72 - 0.44 × x / 100
careerWeight = remaining × careerShare
lifeWeight = remaining × (1 - careerShare)
```

行业不是“探索中”时使用 `careerWeight`。`lifeWeight` 在所选兴趣之间平分。`lively` 使用现有演出/活动线索。城市信号为0–3，换算到0–1；只有 `sourced` 或 `editorial` 证据状态算已知。

缺失证据使用中性效用0.5并降低资料覆盖，因此不会凭空拉开城市差距。阅读、游泳和健身等选择会保留并生成任务，但当前多数城市没有足够同口径资料。

内部值：

```text
fit = Σ(weight × utility) / Σ(active weight)
coverage = Σ(known weight) / Σ(active weight)
```

`fit` 仅用于候选先后，主界面不展示总分。`coverage` 只表示当前输入涉及的资料覆盖，不是准确率或置信度。

## 预算与气候约束

预算和气候不参与上述偏好分。每座城市先得到三种约束状态：

1. `clear`：预算不低于当前城市级基准，且已知气候资料没有触发红线；
2. `unknown`：租金或任一气候红线资料缺失；
3. `conditional`：预算低于基准，或已知气候强度达到冲突阈值。

候选顺序先按 `clear → unknown → conditional`，再按内部偏好分、资料覆盖和城市 ID 排序。未知排在已知冲突前只是探索顺序，不表示它已经通过红线。

预算比较使用2026年1月30–60㎡住宅平均套租：

| 城市 | 元/月 |
| --- | ---: |
| 武汉 | 1493 |
| 成都 | 1730 |
| 南京 | 2248 |
| 广州 | 2381 |
| 杭州 | 2638 |
| 深圳 | 3696 |
| 上海 | 3900 |
| 北京 | 4482 |

当预算达到基准后，约束只标记为当前无已知冲突，不继续产生加分。它不能证明目标工作地附近有合适房源。来源与口径见 [data-sources.md](data-sources.md)。

## 三幕规则

用户从候选中亲手留下左右两城。`buildDuelRounds` 固定生成：

1. `career`：宽行业线索与具体岗位未知；
2. `daily`：优先选择双方证据覆盖更高、差异更可见的兴趣；
3. `landing`：租金、住房、通勤与气候红线。

每幕只能记录 `left`、`right` 或 `tie`。三幕结束不统计多数票，也不产生赢家。

原始倾向由 `analyzeAssumption` 按关键词生成审计：

- 成本/租金：列出两城同口径基准和具体房源限制；
- 机会/发展/具身/AI：指出宽行业不能证明岗位、薪资和录取；
- 好玩/演出：指出活动存在不等于工作日可重复；
- WLB/压力：指出它主要属于公司、团队和岗位。

这不是自然语言事实判定器；未命中的句子会明确标为待验证。

## 决胜问题与任务

本地规则优先选择平局或证据不可比的一幕：

- 发展：两城各找5个真实在招岗位；
- 落地：两城各找3个预算内住处并连接工作地、通勤和押金；
- 日常：把所选活动和气候红线设计成一次普通工作日核验。

原生系统 Agent 可返回同一三类维度中的一个问题与一个任务，但不能改变任何城市状态。用户确认“加入核验清单”后才保存。

## 固定验收

`tests/departure.test.mjs`、`tests/duel.test.mjs` 和 `tests/experience-state.test.mjs` 覆盖：

- 约束与偏好分离；
- 红线未知不算通过；
- 预算覆盖后不制造额外优势；
- 原始倾向不改变排序；
- 三幕投票不自动选择首城；
- 小陈、小雷关键假设提示；
- 五阶段刷新恢复与旧存档迁移。

这些检查证明程序按规则运行，不证明规则能预测个人结果。真实有效性仍需用求职样本、房源与通勤调查、健康体验和用户后续行动验证。
