# 毕业第一站 · 城市红娘

**毕业去哪里？先和一座城市约会，再决定要不要继续了解。**

![毕业第一站 · 城市红娘](docs/cover.png)

**GOSIM Agentic App 2026｜MOST暴躁队｜Leinstein** · [初赛提交回执](https://github.com/gosimfoundation/hackathon-agenticapp26/issues/13#issuecomment-5964776262)

城市红娘帮助准备毕业、找工作或考虑换城的人，把工作和日常生活的取舍想清楚。填写资料，让猫或狗问一个关键问题，先认识一座城市；告诉它哪里不合适，再看看推荐为什么变了。

它给你的是**值得进一步了解的城市、具体理由、需要接受的代价，以及还要核实的条件**。当前版本不预测幸福概率，也不保证就业或住房结果。

## 怎么玩

1. **选一位红娘。** INTJ 黑白德文猫说重点，ENFP 线条小狗更有画面感；随时切换，答案和排序保留。
2. **留一点资料。** 填写目前状态、职业方向和生活兴趣；不确定的可以跳过。
3. **回答一个关键问题。** 比如第一站更想优先找对工作，还是把日常生活过舒服。
4. **认识一座城市。** 看具体资料、生活场景和代价，表达喜欢、担忧或明确拒绝。
5. **补答，再比较。** 第二问跟着反馈走；结果解释变化，并保留并列候选和未知条件。
6. **收好城市车票。** 下载 PNG 或复制摘要，把这次探索留给自己，也可以分享。

## 本地试玩

下载或克隆仓库后，在项目根目录运行：

```sh
node serve.mjs
```

随后在同一台电脑的浏览器打开 **http://127.0.0.1:4318**。这是启动后的本地地址，不是公开 Demo，也不能直接发给他人在手机上访问。

Web 版使用原生 HTML、CSS 和 JavaScript：**无需安装第三方依赖、无需构建、无需 API Key**。需要可运行本项目 ESM 和 Node 内置测试的 Node.js 环境。结束试玩时，在终端按 `Ctrl+C` 关闭服务。

当前提供本地试玩方式，尚无公开在线 Demo 或正式 App Hub 安装链接。

## 推荐从哪里来

初版覆盖**武汉、上海、杭州、成都、广州、南京**，整理了 16 条公开来源。所有特征都保留依据、人工整理标记和未知项；生活场景属于创作表达，不概括城市居民的人格。

匹配由可查看的本地规则完成：

- 本人确认的行业、生活需求、工作生活优先级、气候偏好与明确拒绝会影响结果。
- 未知信息不加分，也不会把剩余项目重新放大；同分时明确说明分不出先后。
- 反馈可以改变下一问与推荐。资料不足以支持变化时，保留原排序并说明还需要核实什么。
- MBTI、星座、年龄、院校和欣赏的人格标签只作为自我介绍，**不参与本版排序**；猫狗角色也不改变结果。

城市资料不能替代具体岗位、房源和通勤调查。当前预算只形成核验条件，不用城市成本印象推算“你一定租得起”；没有街区证据，也不会承诺住处附近安静、运动方便。

规则见 [匹配模型](docs/matching-model.md)，数据范围与来源见 [六城资料说明](docs/data-sources.md)。

## 两个版本，分别验证了什么

| 版本 | 已完成 | 尚未完成 |
| --- | --- | --- |
| **Web 体验版** | 三页资料、两轮推荐、反馈改推、来源查看、本地恢复与清除、PNG 车票和摘要分享；已做浏览器操作验收 | 公开在线部署、实体手机与更多浏览器验证；没有调用大模型 |
| **OctoScript 参赛包** | 真实 Makepad card-host 中的两轮操作、明确拒绝、存档、重启恢复、清除和滚动；本地 unsigned App Hub gate 通过 | 本应用的完整 OctoSense Shell 安装、真实 MiniMax/Kimi 调用、正式签名及 App Hub 公开审核；不含 Web 的 PNG 分享功能 |

原生包已提供系统 Agent 说明入口。在本次 card-host 验收中，宿主返回 `no service answers "octos" on this device`，应用正确显示不可用并保留本地结果。**这证明了不可用时的处理，不代表真实模型已经接通。**

详细证据：[Web 验收记录](docs/web-qa.md) · [OctoScript 验收与运行记录](docs/octosense.md) · [公开版本与发布状态](docs/publication.md)。

## 源码结构

```text
web/                    页面、交互与分享车票
core/matcher.mjs         可解释的确定性匹配引擎
core/questions.mjs       两轮问题与反馈状态更新
data/cities.json         六城特点、证据、来源与未知项
bundle/                 OctoScript 原生参赛包及真实截图
tools/                  原生包生成与本地验收工具
tests/                  匹配规则及真实城市数据集成测试
qa/                     浏览器验收脚本、结果与截图
docs/                   产品设计、规则、数据和验证说明
serve.mjs               无第三方依赖的本地 Web 服务
```

Web 与原生版共用城市资料。原生版由 `tools/main.template.splash` 和数据生成；修改时请使用模板及 `tools/build_bundle.py`，不要只改生成后的 `bundle/main.splash`。运行原生包还需要独立准备 OctoSense / Makepad 工具，仓库不包含平台二进制。

## 验证

在项目根目录运行：

```sh
node --test tests/*.test.mjs
```

2026-10-03 的记录为 **25 项测试通过，0 失败，0 跳过**。测试覆盖硬条件、未知证据、重复权重、明确拒绝、同分、资料修订、两轮不同回答改变排序，以及具体推荐理由与来源。

另已实际验证桌面、320 / 375 / 390px 模拟手机尺寸、两轮操作、本地恢复与清除、分享下载及隐私。浏览器回归脚本在 `qa/browser-smoke.mjs`，运行它需要另行准备 Playwright 与 Chromium；这不影响无依赖的 Web 试玩。上述验证证明流程运行情况，不证明现实城市推荐准确性或真实用户满意度。

## 资料与分享

Web 资料保存在当前浏览器，可通过“本机资料”清除；原生版使用应用本地存储。Web 试玩不向模型或外部服务上传表单，访问城市来源链接时会打开对应外部站点。

默认分享车票和摘要不包含昵称、年龄、院校、预算或欣赏的人的信息。公开仓库中的验收材料使用合成测试资料。

欢迎用仓库 Issue 报告操作问题、补充有来源的城市资料，或指出哪条推荐不符合自己的生活。最有帮助的反馈是：**你在意什么、哪条依据不成立、还缺什么信息。**
