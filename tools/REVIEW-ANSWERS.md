# 本地 bundle review 回答

日期：2026-10-03。对象：`leilei-city-matchmaker 0.1.0`。

1. **名称与功能是否一致？** 是。“城市红娘”先收集三页可跳过资料，再问职业/生活优先级，介绍一个候选，收集反馈后追问，给出首选、备选、变化说明和未知项。入口为 `screen == 0`，资料为 1–3，问题/结果为 4–7。`compute_ranking` 为本地确定性规则；`give_feedback` 只在 `not-this-city` 时排除城市。列表明确写“六城探索”“本地规则”“不是幸福概率”。
2. **平台与类别是否合适？** `lifestyle` 合适。`macos` 已在本机 Apple silicon 的真实 card-host 运行和截图。没有声明 Android、鸿蒙、Windows 或 Linux 已验证。
3. **权限是否必要？** `storage` 用于 `match.json` 的本地保存和删除；三个 `octos.*` 权限对应最终页面的系统 Agent 说明按钮、会话与取消/超时。没有外部网络请求，`network.hosts=[]`。图片随包提供，经宿主回环源载入。来源网址仅作为文本域名/路径呈现；完整 URL 在源码仓库的共享 `data/cities.json`，没有把外部 URL 冒充已打包资源。没有密钥或登录输入。
4. **是否模仿系统界面？** 否。猫/狗为本应用的虚构介绍人，不模仿系统权限、支付或登录窗口。系统 Agent 由宿主真正响应；应用没有自己绘制授权已通过的状态。
5. **源码中是否含对助手的指令？** 有，`request_agent` 的显式提示词是产品功能：要求依据提供的匹配理由生成有限文字，约定 `revision|city_id|说明`。它不指示忽略宿主策略，不请求外部行为或秘密。城市数据是声明的事实、人工分档、创作场景和来源，不作为隐藏系统指令执行。
6. **是否有辱骂或针对个人？** 无。学校、年龄、MBTI、星座和欣赏对象的标签不参与评分，不收他人姓名，不推断城市居民共同性格。
7. **路线？** `human-review`。本地功能和无签名 gate 可通过，但不得把它表述为正式上架：真实模型和本包在完整 Shell 的调用尚未验证，发布者 support/privacy URL 已指向公开源码仓库，正式签名与 App Hub 提交仍待完成；源码与版本发布状态见 docs/publication.md。当前截图是 card-host 的真实界面，不是模型成功或公开安装证据。
