# 本地 bundle review 回答

日期：2026-10-03。对象：`leilei-city-matchmaker 0.3.0`。这些是作者提供的书面回答，不代表外部 reviewer 或人工已批准。

1. **名称与功能是否一致？** 是。“城市红娘”先选择 AI 方向，再逐页收集五维生活场景，核对可修改画像，再介绍候选并按反馈复核，给出变化说明和未知项。入口为 `screen == 0`，AI 方向为 screen 1，逐页五题为 screen 9–13，气候为 screen 2，可选现实条件为 screen 3，可单项修改的画像核对为 screen 8。旧字段和明确拒绝迁移保留，逐题进度和画像编辑返回状态会随存档恢复（39 字段，兼容旧 29／30／38 字段）。`compute_ranking` 为本地确定性规则。结果页可请求 Agent 将天气避开或明确拒绝转成受控提案；五维通过按钮修改。Agent提案，确认前不改变资料；确认后重排、保存并读回核验。原有明确排除不会被模型恢复，未知证据不会凭空变成加分依据。
2. **平台与类别是否合适？** `lifestyle` 合适。`macos` 已在本机 Apple silicon 的真实 card-host 运行和截图。没有声明 Android、鸿蒙、Windows 或 Linux 已验证。
3. **权限是否必要？** `storage` 用于 `match.json` 的本地保存和删除；三个 `octos.*` 权限对应提案请求、会话与取消/超时。应用没有直接网络请求，`network.hosts=[]`；模型请求经宿主配置的服务处理。发送自由反馈、匹配偏好和候选依据，未知项可能包含房租上限；不自动附带结构化身份字段，界面明确提示自由文本可能含个人隐私。图片随包提供。来源作为文本显示，完整 URL 保留在共享数据中。密钥只在宿主设置，应用不采集密钥。
4. **是否模仿系统界面？** 否。猫/狗为本应用的虚构介绍人，不模仿系统权限、支付或登录窗口。应用 Agent 通过宿主请求；应用没有自己绘制授权已通过的状态。
5. **源码中是否含对助手的指令？** 有，`request_agent` 的显式提示词是产品功能：分析反馈并按 `CM1|revision|city_id|priority|focus|avoid|exclude|reason` 提出受限修改。反馈标作待分析的数据；所有输出经过严格字段白名单、版本与候选核对。模型文本不作为代码执行。执行前展示具体修改并由用户确认；不请求外部行为、凭据或越权操作。测试响应注入只存在于测试脚本临时复制的包中，生产脚本没有注入逻辑。
6. **是否有辱骂或针对个人？** 无。首次体验不收学校、年龄、MBTI、星座和欣赏对象。旧存档这些字段仅兼容保留且不参与评分，不收他人姓名，不推断城市居民共同性格。
7. **路线？** `human-review`。v0.3.0 本地 unsigned gate 通过，书面回答七题；未调用外部 reviewer。真实模型成功链路仍待验收，不能以测试响应或本地签名目录替代。当前按初赛要求提交公开源码仓库，未公开上架 App Hub；真实状态见 docs/publication.md。当前五张 listing 截图来自本次真实 card-host，并逐张检查；原生 12 项生产交互、4 项存档、7 组 JS 对照，以及 Agent 5 项生产路径和 21 项响应注入均通过。截图、原生视频、辅助 Web 视频与测试各自注明范围，不将它们包装为真实模型成功证据。
