# 本地 bundle review 回答

日期：2026-10-05。对象：`leilei-city-matchmaker 0.4.0`。以下是作者回答，不是外部审核结论。

1. **名称与功能是否一致？** 是。城市红娘打开直接展示一城、一句生活吸引点和一个代价。留第一城继续浏览，留两城进入对比；最多收藏两城。“下一座”只记录浏览，不排除、不修改五维偏好。难取舍时，只有两城对应未填偏好存在已知差异才可选追问；明确回答才改变那一维，结果说明线索和未知，不承诺幸福或录取概率。资料随时补，编辑后回原浏览或对比位置。
2. **平台与类别是否合适？** `lifestyle`；已在 Apple silicon macOS 真实 card-host 验证。场景使用原生 Svg 组件，四张 listing 截图来自该宿主。未声称其他平台或实体手机通过。
3. **权限是否必要？** `storage` 保存本机偏好、浏览、收藏和编辑上下文；`octos.session.open`、`octos.turn.start`、`octos.turn.interrupt` 用于按需请求、取消应用 Agent 提案。`network.hosts=[]`，素材随包，来源仅展示。模型密钥只由宿主管理；自由反馈和匹配依据在点击发送后才通过宿主服务发送，不自动附带结构化身份资料。模型会话可能由宿主保存。
4. **是否模仿系统界面？** 否。猫狗是虚构介绍人，按钮与页面属于本应用；不伪装授权、登录或支付。详情中的应用 Agent 始终绑定实际显示的城市，而非隐藏的排序第一名。
5. **源码中是否含对助手的指令？** 有，`request_agent` 为产品功能提示词，要求 CM1 八段白名单。当前主动建议只追加天气避开或在用户明确拒绝时排除当前详情城市；五维由本人按钮修改。严格检查协议、城市、资料版本与请求序号。建议必须先预览确认，修改反馈、切页、切城或切角色使旧建议失效。模型输出不作为代码执行；测试注入只在临时副本。
6. **是否有辱骂或针对个人？** 无。浏览和收藏不被用来猜人格或训练偏好。旧存档中的学校、年龄、人格字段兼容保留但不评分，也不在新流程收集他人身份。
7. **路线？** `human-review`。本地 unsigned gate 通过，scan 只生成七问材料；没有外部 reviewer、签名或公开上架。本轮真实生产 UI 19 项与 Agent 4 项生产路径、23 项明确标记的响应注入安全检查通过；不把这些说成真实模型成功。5 项存档合同、8 步原生／JS 浏览状态对照、7 组排名／区间／试城计划对照全部通过，见 `qa/native-discovery-contract.json`；合同仅在临时副本抑制界面刷新，生产 UI 另行真实操作验证。
